# Security Policy & Responsible Disclosure

## Prototype Warning (Testnet Only)

**Setu is an unaudited research and hackathon prototype running on the Stellar testnet.**
- It is **not** production-secure, **not** audited, and **not** a regulated financial service.
- Do **not** deploy these contracts to Stellar mainnet or use them with real funds or real personal/compliance data.
- See [docs/privacy-compliance-limitations.md](docs/privacy-compliance-limitations.md) for the complete list of cryptographic, privacy, and compliance limitations.

---

## Reporting a Vulnerability

If you discover a security vulnerability, soundness bug, or unintended privacy leak in Setu:

1. **Do NOT open a public GitHub issue** with live exploit payloads or secret keys.
2. **Use GitHub Private Vulnerability Reporting** (`Security` -> `Report a vulnerability` on this repository) or contact the repository maintainers privately via GitHub security advisories.
3. Include:
   - Affected component (`contract/`, `circuits/`, `libs/zk/`, `libs/lean-imt/`, `cli/circom2soroban/`, or `site/`).
   - Minimal reproduction steps or a self-contained Rust/Circom/Node test case.
   - Impact assessment (e.g., forged withdrawal proof, double-spend bypass, non-canonical signal acceptance, or unintended witness leak).

Because Setu is a prototype maintained asynchronously, we aim to acknowledge reports within **7 days** and track fixes via public hardening issues once triaged.

## Out of Scope (Known Prototype Limitations)

The following items are **already documented prototype trade-offs** in [docs/privacy-compliance-limitations.md](docs/privacy-compliance-limitations.md) and do not need new vulnerability reports unless you have a concrete hardening PR:

1. **Single-party local trusted setup:** `.ptau` and `.zkey` files generated by `setup.sh` / `run.sh` are single-contributor test artifacts (`not production-secure`).
2. **Prover-asserted `recipientId` and `purpose` in v1/v2:** `circuits/disclosure.circom` hashes `recipientId` and `purpose` into `discloseHash`, but does not bind them at deposit time.
3. **Legacy `associationRoot == 0` circuit path:** `circuits/main.circom` skips the association Merkle check when `associationRoot == 0`, which the Soroban contract blocks on-chain via `has_association_set()`.
4. **On-chain `verify_disclosure` linkability:** Calling `verify_disclosure` on-chain intentionally publishes the `nullifierHash <-> commitment` link on the public ledger; single-regulator audits should verify off-chain.
5. **Mock fiat/anchor corridors:** The USDC on-ramp and INR off-ramp flows in `site/` are UI stubs with no live SEP-24/SEP-31 connectivity.
